# Agent Instructions — rust-xgboost

## General

- Use American English spelling in all prose and comments.
- All code changes must pass `cargo clippy` and `cargo fmt` before committing.
- Every `#[allow(...)]` attribute must include `reason = "..."`.
- **Never commit directly to `main` or `develop`.** Always create a feature branch
  first (`git checkout -b feature/<short-description>`).

## Repository layout

```
rust-xgboost/
  src/                  # Rust crate (crate name: xgb)
  xgboost-sys/
    build.rs            # Build script — builds libxgboost from source, governs linking
    src/lib.rs          # FFI bindings (generated by bindgen)
    xgboost/            # XGBoost source (git submodule — do not modify)
```

XGBoost is **always built from source** as a **static, CPU-only** library on every
platform — there are no prebuilt binaries committed to this repo and no Cargo features
for selecting prebuilt/dynamic/CUDA builds. `build.rs` is the single source of truth for
the CMake configuration and link directives.

## `build.rs` — critical invariants

### Use `TARGET` env var, not `cfg!()`

`cfg!()` macros in `build.rs` reflect the **host** OS, not the cross-compilation
target. Always use `env::var("TARGET")` for any target-conditional logic:

```rust
let target = env::var("TARGET").unwrap();
if target.contains("android") { ... }
if target.contains("apple")   { ... }
if target.contains("linux")   { ... }
```

### `cargo:rustc-link-arg` does not propagate

Link flags emitted as `cargo:rustc-link-arg` from a **dependency's** build script
are silently ignored when linking the final binary. Use `cargo:rustc-link-lib` and
`cargo:rustc-link-search` instead — these do propagate.

### Copying archives into the `deps/` directory

The Rust toolchain already adds `$OUT_DIR/../../../deps/` to the linker search
path. The cleanest way to link arbitrary static archives (e.g. NDK libc++ libs)
from a dependency build script is to copy them into that directory and emit
`cargo:rustc-link-lib=static=<name>`.

```rust
let deps_path = dunce::canonicalize(
    Path::new(&format!("{}/../../../deps", out_dir))
).unwrap();
fs::copy(&src_archive, deps_path.join("libfoo.a")).unwrap();
println!("cargo:rustc-link-search=native={}", deps_path.display());
println!("cargo:rustc-link-lib=static=foo");
```

## Android (aarch64-linux-android)

### Background

- `libxgboost.a` and `libdmlc.a` for Android arm64 are cross-compiled from
  source via the NDK toolchain (see the Android branch in `build.rs`). They are
  linked **statically** so no `.so` files need to be present on-device at runtime.
- The libraries were built against **API 26** (Android 8.0, Oreo).
  - `pthread_getname_np` was introduced in API 26. Building against an earlier
    API level requires patching `xgboost/src/common/threading_utils.cc`, which
    is undesirable because `xgboost/` is a git submodule of an upstream repo
    we do not fork. **Keep the minimum at API 26** and avoid submodule edits.
- The C++ runtime is linked statically via `libc++_static.a` + `libc++abi.a`,
  copied from the NDK sysroot into the `deps/` directory at build time (see
  `ndk_sysroot_lib_dir()` in `build.rs`).

### Prerequisites (one-time setup)

```bash
# 1. cargo-ndk wrapper
cargo install cargo-ndk

# 2. Rust target
rustup target add aarch64-linux-android

# 3. Android NDK — install via Android Studio SDK Manager or:
sdkmanager "ndk;29.0.14206865"   # or whichever version

# 4. Point to the NDK
export ANDROID_NDK_HOME=$HOME/Library/Android/sdk/ndk/<version>
```

`cargo-ndk` exports `NDK_PATH` (pointing to
`…/toolchains/llvm/prebuilt/<host>/bin`) and `ANDROID_NDK_HOME` to the
build script; `build.rs` uses these to locate the NDK sysroot.

### Building

No special steps are needed — `build.rs` cross-compiles XGBoost from source with
the NDK toolchain automatically at build time:

```bash
cargo ndk -t arm64-v8a -P 26 build
```

### Starting the emulator

Use an **x86_64 Android emulator** with an **arm64-v8a system image** (or a
physical arm64 device). The emulator must be running before executing tests.

```bash
# List available AVDs
emulator -list-avds

# Start one (background)
emulator -avd <avd-name> -no-snapshot-load &

# Confirm device is online
adb wait-for-device
adb shell getprop ro.product.cpu.abi   # should include arm64-v8a
```

> **Important:** Production (Google Play) emulator images run `adbd` as a
> non-root user (`adbd cannot run as root in production builds`). Use a
> **Google APIs** image, not a **Google Play** image, if you need `adb root`.

### Pushing test data

Tests that load data files from disk look for them at
`/data/local/tmp/xgboost-sys/xgboost/demo/data/` on the device (the
`#[cfg(target_os = "android")]` path in `src/dmatrix.rs` and
`src/booster.rs`). Push the data once per emulator session:

```bash
adb push xgboost-sys/xgboost/demo/data \
         /data/local/tmp/xgboost-sys/xgboost/demo/data
```

### Running tests

`cargo-ndk-runner` executes the test binary on-device via `adb shell`. It
starts the binary with CWD `/` (the root filesystem, which is read-only on
production images), so all data paths must be absolute.

```bash
# Unit and integration tests — parallel is fine
cargo ndk -t arm64-v8a -P 26 test --lib

# Doctests — MUST be single-threaded
# cargo-ndk-runner pushes every doctest binary to the same device path
# (/data/local/tmp/rust_out). Running them in parallel causes "Text file busy"
# and "No such file or directory" errors.
cargo ndk -t arm64-v8a -P 26 test --doc -- --test-threads=1
```

Expected result: **27 lib tests + 7 doctests = 34 passed, 0 failed**.

### How the Android build works

`build.rs` cross-compiles XGBoost from source on every `cargo ndk` build using the
NDK CMake toolchain — equivalent to:

```bash
cmake -S xgboost-sys/xgboost -B "$BUILD_DIR" \
  -DCMAKE_TOOLCHAIN_FILE="$ANDROID_NDK_HOME/build/cmake/android.toolchain.cmake" \
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-26 \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DBUILD_STATIC_LIB=ON -DBUILD_SHARED_LIBS=OFF \
  -DUSE_OPENMP=OFF -DUSE_CUDA=OFF -DUSE_NCCL=OFF -GNinja
```

There are no committed archives to rebuild or strip.

**Do not patch `xgboost-sys/xgboost/` sources.** The submodule tracks an
upstream repo without a fork. Instead, choose a build configuration that
avoids the need (API 26 handles `pthread_getname_np`; `USE_OPENMP=OFF`
avoids the NDK OpenMP absence).

### Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `ld.lld: error: unable to find library -lxgboost` | CMake build did not produce the archive | Check the CMake/Ninja step in `build.rs` succeeded; ensure cmake + the NDK toolchain are available |
| `ld.lld: undefined symbol: operator new` | Missing C++ runtime | `build.rs` must copy `libc++_static.a`/`libc++abi.a` from NDK sysroot and emit `cargo:rustc-link-lib=static=c++_static` |
| `pthread_getname_np@LIBC_O` undefined | API level mismatch | Build both the static lib and the Rust binary at the same API level (26). Pass `-P 26` to `cargo ndk`. |
| `pthread_atfork` undefined | NDK sysroot added as `-L` search path causing linker to pick up static `libc.a` | Never add the NDK sysroot lib dir directly to the link search path; copy specific archives to `deps/` instead |
| `library "libc++_shared.so" not found` at runtime | Dynamic `c++_shared` linking | Use static `libc++_static.a` + `libc++abi.a` instead |
| `chmod: /data/local/tmp/rust_out: No such file or directory` in doctests | Parallel doctests all push to the same device path | Add `-- --test-threads=1` to the doctest invocation |
| `Text file busy` in doctests | Same as above (race condition) | Same fix |
| `No such file or directory` for `xgboost-sys/xgboost/demo/data` | Test binary runs with CWD `/` on device | Use `#[cfg(target_os = "android")]` to switch to absolute `/data/local/tmp/...` path; push data with `adb push` first |
| `adbd cannot run as root in production builds` | Google Play emulator image | Switch to a Google APIs image, or work around the need for root |
| `unknown package: 26` from cargo-ndk | Used `-p 26` (cargo package flag) instead of `-P 26` | Use uppercase `-P` for the platform/API level flag |
